# PunchGrow — 제품 스펙 (PRD)

이 문서는 지금까지 정해진 내용을 담는 살아있는 문서입니다. 결정이 바뀌거나 추가될 때마다 이 파일을 갱신합니다. "왜 이렇게 정했는지"는 이 문서가 아니라 `문서/DECISIONS.md`에 기록합니다.

## 제품명

**PunchGrow** (구 가제: DAEMON). Punch(아레나 배틀) + Grow(크리처 성장), 앱의 두 핵심 루프를 그대로 이름에 담았습니다.

## 컨셉 한 줄 요약

Claude Code의 실제 토큰 사용량과 무료 보상으로 얻은 토큰이 크리처의 성장과 가챠 확률에 반영되고, 다른 유저와 아레나에서 배틀하는 모바일 앱. 개발을 많이 할수록 좋은 크리처를 뽑을 가능성이 높아져 AI 코딩 도구를 사용하는 과정 자체를 즐겁게 만든다.

## 핵심 루프

```
Claude Code 토큰 사용량 + 무료 보상
  → PunchGrow 토큰
  → 가챠 기회·희귀 확률 상승
  → 성장·진화
  → 아레나 배틀
  → 랭킹·시즌 보상
```

## 토큰과 보상 규칙 (기획 인터뷰 진행 중)

- 초기 핵심 획득원은 사용자가 Claude Code에서 실제로 사용한 토큰 수치다.
- 별도의 코인·에너지로 환산하지 않고 `토큰`이라는 하나의 잔액을 사용한다.
- 무료 보조 획득원으로 출석 보상, 사용자가 직접 선택하는 보상형 광고, 운영 이벤트·장애 보상 지급을 허용한다.
- 현금 결제, 유료 가챠권, 유료 구독 확률 혜택, 현금 환급·판매·양도는 제공하지 않는다.
- 코딩 활동량은 가챠 횟수뿐 아니라 희귀 크리처 등장 확률도 높인다.
- 확률 상승 상한은 두되 매우 높게 설정하여 헤비 사용자의 우위를 상당 부분 허용한다.
- MVP에서는 작업 내용의 의미·품질이나 의도적 토큰 소비 여부를 판별하지 않는다.
- Claude Code 사용량, 출석, 광고, 운영 보상으로 얻은 토큰은 하나의 잔액으로 합산한다.
- 토큰 획득 내역에서 `Claude Code·출석·광고·운영 보상` 출처를 구분해 표시한다.
- 토큰은 누적 활동 점수만이 아니라 실제로 소비하는 잔액이다.
- 가챠를 실행하거나 크리처 육성에 필요한 아이템을 구매하면 토큰이 차감된다.
- MVP 기본 육성 아이템은 `먹이(경험치 상승)`, `훈련 도구(특정 스탯 상승)`, `진화 재료(진화 조건 충족)`로 구성한다.
- macOS MVP에서 먹이 1개는 보유 토큰 100,000개로 구매한다. 팝업의 `먹이 +1` 액션에서 즉시 구매하며, 잔액 차감과 인벤토리 증가는 하나의 저장 작업으로 처리한다.
- macOS MVP의 `대형 먹이`는 일반 먹이와 별도 보관하며 1개당 500,000 토큰이다. 사용 시 XP +200, 친밀도 +10을 주고, 구매·급여 모두 길게 눌러 가속 연속 실행할 수 있다. 기존 스키마 2 세이브에는 대형 먹이 수량을 0으로 보완한다.
- 첫 버전부터 다음 아이템 범주를 모두 포함한다.
  - 먹이: 경험치 상승
  - 훈련 도구: 특정 스탯 상승
  - 진화 재료: 진화 조건 충족
  - 돌봄 아이템: 친밀도·기분·컨디션 회복
  - 스킬북: 전투 기술 습득
  - 부화 촉진기: 알 부화 시간 단축
  - 탐험권: 재료를 얻는 탐험 참여
  - 장식품: 둥지와 크리처 외형 꾸미기
  - 회복약: 아레나 이후 체력 회복

## Claude Code·Codex 사용량 수집 구조 (확정)

모바일 앱만으로 PC/Mac의 Claude Code 사용량을 읽을 수 없으므로 로컬 수집기가 필요하다.

```
사용자의 Claude Code
  → 공식 OpenTelemetry 토큰 메트릭
  → PC/Mac용 PunchGrow 수집기
  → PunchGrow 동기화 서버
  → iOS·Android 앱
```

- macOS 1차 제품은 `~/.claude/projects/**/*.jsonl`의 assistant usage와 `~/.codex/sessions/**/*.jsonl`의 `token_count.last_token_usage`를 로컬에서 자동 탐색한다.
- 수집기는 사용자의 컴퓨터에 설치하고 모바일 계정과 QR 코드 또는 연결번호로 연동한다.
- 프롬프트, 응답, 소스코드, 파일 경로, 명령어는 수집하지 않는다.
- 이메일과 Claude 계정 식별자는 로컬에서 제거하고 토큰 수치, 시간, 익명 PunchGrow 식별자만 암호화해 전송한다.
- JSONL 구조는 안정된 공개 API가 아니므로 파서 버전과 fixture 회귀 테스트를 유지한다. Claude는 `(message.id, requestId)` keep-max 중복 제거, Codex는 캐시 입력 분리와 fork replay 억제를 적용한다.
- 최초 스캔은 기존 사용량을 금주 통계에만 표시하고 소비 가능한 토큰으로 소급 지급하지 않는다. 이후 새 증가분만 적립한다.
- 증분 캐시에는 해시 식별자, 토큰 수치, 시각, 파일 크기·오프셋·해시만 저장한다. 로그 원문, 프롬프트, 응답, 프로젝트명, 절대 경로, 원본 메시지 ID는 저장하지 않는다.
- 사용량 수집은 명시적 동의 방식이며 연결 해제, 설정 복구, 데이터 삭제 기능을 제공한다.

## 톤 & 아트 디렉션

다크 터미널 베이스 + 네온 라임/마젠타/시안. 두꺼운 테두리와 하드 섀도우로 장난스러운 게임 UI, 데이터는 모노스페이스 폰트로 진지하게 표현.

크리처 아트는 `Cute Clarity v2` 기본 240종과 4원소 원초 계보 16종, 총 256종을 개발본에 활성화했다. 큰 얼굴과 단순한 실루엣, `#08111F` 카드 배경을 공통 언어로 사용하며 세부 기준은 `문서/CREATURE_DESIGN_BIBLE.md`와 `문서/ELEMENTAL_ORIGINS.md`를 따른다.

## 크리처 세계관·등급·가챠 (기획 확정, 상세 디자인 후속)

### 세계관과 창작 원칙

- 모든 크리처는 하나의 공통 디지털 신화 세계에 속한다.
- 그리스·로마 신화의 신계, 영웅, 괴물, 운명과 변신 구조를 코드·AI·네트워크·시스템 개념으로 재해석한다.
- 원전 이름을 직접 사용하지 않고 크리처, 지역, 종족, 사건과 진화 계열은 PunchGrow 고유 명칭과 외형으로 제작한다.
- 귀여운 초기형부터 강렬하고 위압적인 최종형까지 혼합하며, 각 계열에 기원·성격·갈등·진화 서사를 부여한다.

### 진화와 변종

- 계열마다 2·3·4단계 진화를 혼합한다.
- 분기 진화, 혼합 진화, 조건부 특수 진화와 변이형을 제공한다.
- 변이형은 능력·외형·서사 또는 진화가 다른 별도 도감 항목이다.
- 유니크 컬러는 기본 크리처와 능력·진화·스토리·도감 슬롯을 공유하는 희귀 색상 변종이다.
- 유니크 컬러는 등급 판정과 독립적으로 모든 가챠 결과에 0.1% 확률로 등장한다.
- 유니크 컬러는 능력 우위 없이 외형과 수집 가치만 가진다.
- 진화는 사용자가 방향을 만들고 최종 결과에 확률이 작용하는 `통제 가능한 랜덤` 방식이다.
- 먹이, 훈련, 친밀도, 아이템, 시간과 기타 조건이 진화 후보별 확률을 바꾼다.
- 희귀 변이형과 특수 진화는 낮은 확률의 후보로 포함할 수 있다.
- 진화 전에는 정확한 결과를 확정 표시하지 않고 현재 성향과 감지된 진화 신호를 보여준다.
- 완료된 진화는 되돌릴 수 없다.
- 진화 판정 전에 `재연산권`을 사용하면 후보별 확률을 다시 계산할 수 있다.
- 진화 완료 후 다른 결과를 원하면 같은 시작종의 새 개체를 다시 육성해야 한다.
- `통제 가능한 랜덤`·`재연산권`·진화 전 결과 미확정 표시는 모바일·웹 전용 레거시 기획이다. macOS는 이 셋을 구현하지 않는다 — 대신 결정론적 선호 지정과 진화 순간 10% 변이 확률 발동(수락/거절)을 사용한다. 상세는 `macOS 확정 성장 규칙`을 참고한다.

### 첫 출시 도감 규모

- 시작 크리처 계열: 64종
- 일반 진화형: 133종
- 분기·혼합·특수 진화: 34종
- 별도 도감 변이형: 약 25종
- 첫 출시 전체 도감: 256종
- 유니크 컬러는 기본 도감 슬롯을 공유하므로 256종에 포함하지 않는다.
- 추가된 4개 계보는 물·불·바람·흙의 근원 명령을 상징하는 `PROCESS → AGENT → DAEMON → ORIGIN` 4단계 독립 계보다. 최종형은 일반 ORIGIN과 같은 희귀도를 유지하되 공통 원초 문장으로 구분한다.
- 위 콘텐츠를 시즌 업데이트로 미루지 않고 첫 출시 범위에 포함한다.

### 동시 육성

- 사용자는 여러 크리처를 동시에 보유하고 육성할 수 있다.
- 특정 크리처의 최종 진화 여부는 다음 가챠를 제한하지 않는다.
- 보유 토큰이 가챠 1회 비용 이상이면 별도의 누적 사용량·레벨·진화 해금 조건 없이 반복해서 뽑을 수 있다.
- 사용자에게 보이는 일일 가챠 횟수 제한은 두지 않는다.
- 서버는 중복 요청·자동 클릭 방지 목적의 짧은 기술적 속도 제한만 적용한다.
- 크리처 수집은 무작위 뽑기 반복이 아니라 원하는 진화 분기를 직접 골라 계보를 넓혀가는 과정이다. 256종 전체를 실질적으로 완주할 수 있는지는 플랫폼별 진화 경제에 따라 달라진다 — macOS의 실측 비용과 소요 기간은 `macOS 확정 성장 규칙`을 참고한다.
- 가챠 1회 가격은 알파 기준 500,000토큰이다.
- 가격은 서버 설정값으로 관리해 알파 사용량 데이터와 경제 시뮬레이션 결과에 따라 앱 업데이트 없이 조정할 수 있다.
- 같은 시작 크리처를 중복 획득해도 자동 분해하지 않고 별도 개체로 보유한다.
- 같은 종의 복수 개체를 서로 다르게 육성해 진화 분기와 변이형을 수집할 수 있다.
- 같은 종도 개체 생성 시 성격, STR·AGI·WIT 성장 적성, 선호 먹이가 무작위로 달라진다.
- 개체 특성은 종의 기본 정체성을 유지하면서 성장 속도와 진화 후보별 확률에 영향을 준다.

### 6단계 디지털 신화 등급(모바일·웹 기획)

낮은 순서부터 `PROCESS → AGENT → DAEMON → ORACLE → ARCHITECT → ORIGIN`을 사용한다. 등급은 희귀도뿐 아니라 세계 안에서의 존재 권한과 영향력을 나타낸다.

| 등급 | 알파 기본 확률 | 최대 활동 보너스 적용 |
|---|---:|---:|
| PROCESS | 55% | 40% |
| AGENT | 25% | 26% |
| DAEMON | 12% | 16% |
| ORACLE | 6% | 11% |
| ARCHITECT | 1.8% | 6% |
| ORIGIN | 0.2% | 1% |

- 위 수치는 알파 기준안이며 가챠 시뮬레이션과 플레이 테스트로 조정한다.
- 이 등급별 직접 가챠 확률과 ORIGIN 천장은 모바일·웹의 레거시 기획이다. macOS 실행 규칙은 아래 `macOS 확정 성장 규칙`을 따른다.
- 희귀 확률과 현재 적용 중인 활동 보너스를 사용자에게 공개한다.
- 금주 Claude Code·Codex 검증 사용량 5,000,000토큰에서 최대 활동 보너스에 도달하며, 그 사이는 선형 보간한다.
- 300회 연속 ORIGIN 미등장 시 다음 가챠에서 ORIGIN을 확정한다.
- ORIGIN 획득 시 천장 카운트는 0으로 초기화하며 현재 진행도를 공개한다.
- 유니크 컬러 0.1%에는 천장 보장을 적용하지 않는다.

### 크리처 디자인 작업서 요구사항

상세 제작 기준은 `문서/CREATURE_DESIGN_BIBLE.md`를 정본으로 사용한다.

Google Antigravity에서 일관된 디자인을 생성·검토할 수 있도록 다음 내용을 포함한 별도 작업서를 작성한다.

- 공통 세계관, 시대, 지역, 세력과 디지털 신화 규칙
- 크리처 계열별 신화 모티프와 독자적 재해석
- 이름, 한 줄 정체성, 기원, 성격, 욕망, 갈등과 도감 서사
- 정면·측면·후면 실루엣, 크기, 비율, 해부 구조와 대표 포즈
- 재질, 표면, 발광 부위, 주·보조·강조 색상과 등급별 시각 언어
- 2·3·4단계 및 분기·혼합·특수 진화의 형태 연속성
- 변이형의 구조 변화와 유니크 컬러 팔레트 규칙
- 대기, 기쁨, 배고픔, 수면, 공격, 피격, 진화 애니메이션 요구사항
- 모바일 홈, 도감 카드, 상세 화면과 전투 화면별 가독성 기준
- 포켓몬 등 기존 IP와 유사해지지 않도록 하는 금지 요소
- 남색 카드 배경 마스터, 360×360 모바일 파생본, 파일명과 버전형 자산 팩 관리 규격

### 크리처 시각 방향 (확정)

## macOS 오픈소스 메뉴 막대 앱 (1차 개발 우선순위, 확정)

- 모바일 앱보다 먼저 macOS 메뉴 막대에서 동작하는 완전한 로컬 싱글 플레이 버전을 개발한다.
- 단순 사용량 수집기가 아니라 Claude Code·Codex 토큰 수집, 가챠, 도감, 복수 크리처 육성, 아이템과 진화를 포함한다.
- 회원가입, 서버, 클라우드 동기화, 모바일 데이터 연동, 사용자 간 배틀, 랭킹과 시즌은 제공하지 않는다.
- 사용자가 Connections에서 명시적으로 동의하면 Claude Code와 Codex의 로컬 JSONL 사용량 로그를 10초 간격으로 자동 증분 스캔한다. 동의는 재시작 후 유지되며 언제든 중지하거나 연결 해제와 함께 PunchGrow 증분 캐시를 삭제할 수 있다. 사용자는 Claude/Codex를 별도 PunchGrow 세션으로 시작하거나 OpenTelemetry 명령을 적용할 필요가 없다.
- 기존 OpenTelemetry 수신기와 관리형 Codex 실행기는 진단·호환 UI로 남길 수 있지만 게임 토큰을 지급하지 않는다. 로컬 로그 수집기만 지급 권한을 가져 교차 경로 이중 적립을 막는다.
- Swift·SwiftUI 네이티브 앱으로 만들고 Homebrew Cask 설치를 제공한다.
- 앱과 Mac을 재시작해도 토큰 잔액, 크리처, 도감, 성장·진화·천장 진행도가 보존되어야 한다.
- 설정에서 전체 로컬 데이터를 `.pgrow` 파일로 백업하고 복원할 수 있어야 한다. 파일 위치는 사용자가 선택하며 서버로 전송하지 않는다.
- JSONL 파일 자체에는 민감한 작업 내용이 존재할 수 있으나 PunchGrow 파서는 usage·timestamp·안전한 식별자 필드만 읽는다. 프롬프트, 응답, 소스코드, 명령, 파일 경로, 계정·모델명은 캐시·사용량 기록·`.pgrow` 백업에 저장하거나 외부 전송하지 않는다.
- 첫 공개 버전은 Apple Silicon(M1 이상)만 지원한다. Intel Mac은 실제 수요가 확인되면 후속 검토한다.
- 개발·로컬 테스트는 무료로 진행하고, 정식 Homebrew 공개 직전에 Apple Developer Program에 가입해 Developer ID 서명과 Apple 공증을 적용한다.

### macOS 핵심 화면·동작

- 메뉴 막대 팝업은 일상 플레이 표면이다. `보유 토큰`, Claude Code·Codex `금주 사용량`, 각 통합 상태, 현재 크리처의 이미지·등급·레벨·XP·친밀도, 보유/도감 진행도, 먹이 주기와 가챠를 보여준다.
- 주간 사용률은 토큰량으로 추정하지 않는다. Claude는 로컬 Claude HUD의 OAuth 사용량 캐시 `weeklyPercent`, Codex는 세션 로그의 주간 `rate_limits.primary.used_percent`를 읽어 실제 플랜 한도를 각각 `C n%`, `X n%`로 표시한다. 값이 없거나 아직 수집되지 않은 경우 임의 계산 대신 `확인 대기`로 표시한다.
- `보유 토큰`은 가챠·육성에 쓰는 현재 잔액이며 시작 보너스와 이미 지출한 토큰의 영향을 받는다. `금주 사용량`은 이번 주에 실제로 수신·적립한 Claude Code·Codex 토큰만 보여주므로, 두 수치는 일치할 필요가 없다. 사용량이 0인데 잔액이 있으면 시작 보너스가 포함되었음을 안내한다.
- 여러 크리처를 좌우로 순환 탐색하며 `현재/전체`를 표시한다. `현재 크리처`는 실행 중에만 유지되는 탐색·행동 대상으로, 좌우 탐색과 가챠 성공 시 바뀐다. `대표 크리처`는 사용자가 `대표로 지정`을 누를 때만 로컬 세이브에 보존된다. 먹이는 대표가 아니라 현재 크리처에게 사용한다. 같은 시작종을 여러 마리 보유하면 그룹 내 개체 전환으로 대표 행에 가려진 나머지 개체도 오가며 각각 급여·대표 지정할 수 있다.
- 성공한 가챠는 새 PROCESS 크리처를 현재 대상으로 선택하지만 대표를 자동 변경하지 않는다. 가챠 결과는 `현재 PROCESS`와 선택 가능 경로 기준의 `최대 도달 등급 <등급>`을 별도로 표시한다.
- ORIGIN 계보를 뽑아도 이는 `최대 도달 등급 ORIGIN`인 PROCESS 획득이며 ORIGIN 직접 획득이 아니다. `origin-reveal` 전용 공개는 실제 현재 종이 ORIGIN인 개체를 보유한 상태에만 예약하며, 계보의 최대 도달 등급만으로는 실행하지 않는다.
- 팝업의 Claude·Codex 통합 배지와 큰 창의 Connections는 같은 상태 모델을 사용한다. `중지됨`, `로그 감시 중`, `방금 수신`, `확인 필요`를 텍스트·심볼·색으로 함께 구분한다. `방금 수신`은 검증된 사용량이 실제 적립된 후 10초 동안만 표시한다.
- 큰 창은 `Collection`, `Connections`, `Data & Settings` 세 영역으로 구분한다. Collection은 보유·발견 현황과 잠긴 미발견 실루엣, Connections는 Claude·Codex 설정과 상태, Data & Settings는 알림·사운드·연출 줄이기·백업·복원을 담는다. 상점과 상세 통계는 이번 macOS UX 범위에 포함하지 않는다.

## macOS 확정 성장 규칙 (2026-08-06)

- 가챠는 64종 PROCESS 시작형(stage 1)만 동일 확률로 획득하므로 직접 가챠 등급은 PROCESS 100%다.
- 시작형의 현재 등급과, 변이를 제외한 선택 가능 경로 기준으로 최대로 도달 가능한 등급을 `현재 <등급>`과 `최대 도달 등급 <등급>`으로 구분한다(구 명칭 `성장 잠재력`). 최소 보장 등급을 함께 표시해 아직 선택하지 않은 분기의 낙관 편향을 막는다. 보유 중인 개체는 실제 현재 종부터 이후 경로를 계산하므로, 이미 분기 진화한 개체가 시작형의 기본 경로로 되돌아가 표시되지 않는다. ORIGIN 계보도 가챠 시점에는 `현재 PROCESS`다.
- ORIGIN으로 끝나는 계보가 현재 64개 중 7개이므로 `ORIGIN 계보 확률`은 7/64=10.9%다. 이는 카탈로그에서 파생한 최대 도달 등급 통계이며 `ORIGIN 획득 확률`이나 `ORIGIN 직접 뽑기 10.9%`로 표현하지 않는다.
- 가챠 결과와 메인 크리처 카드는 현재 등급과 최대 도달 등급을 함께 보여준다. 진화도감은 선택 가능 경로와 최대 도달 등급의 근거를 보여주고, 등급표는 `직접 가챠 PROCESS 100%`와 `ORIGIN 계보 10.9%`를 분리해 안내한다.
- 진화도감의 `보유`는 계정 전체 발견 기록이 아니라 선택한 개체가 시작형부터 현재 종까지 실제로 거쳐 온 경로를 뜻한다. 과거 단계는 보유·클릭 가능하고, 현재 단계 이후와 선택하지 않은 같은 단계 분기는 미보유·클릭 불가다. 과거 모습을 메인·메뉴 막대 외형으로 고정해도 실제 종·레벨·경험치는 바뀌지 않는다.
- ORIGIN 전용 공개는 실제 ORIGIN 종을 보유했을 때에만 적용하며, `최대 도달 등급 ORIGIN`인 PROCESS를 획득했을 때는 적용하지 않는다.
- 같은 시작형을 중복 획득한 개체도 모두 저장하지만, 메인 크리처 탐색에는 시작형 종마다 최초 획득 개체 1마리만 표시한다. 같은 시작종을 여러 마리 보유하면 그 대표 행에서 그룹 내 개체 전환으로 나머지 개체도 각각 선택·급여·대표 지정할 수 있다. 표시 개체가 진화해도 원래 가챠 시작형 기준의 목록 자리를 유지한다.
- 진화체는 직접 뽑지 않는다. macOS의 일반 진화 계보는 `normal_evolution`·`branch`·`special`과 확률형 `mutant`만 사용한다. 이 중 선택 가능한 분기·특수 진화 13종은 Lv.15·25·40에서 후보가 2개 이상이면 멈춰 사용자에게 선택을 요청하고, 후보가 1개뿐이면 자동으로 진행된다. `mixed` 10종은 서로 다른 종을 합친 별도 융합 수집품으로 보존하되 일반 진화 후보·잠재력·도감 계보에서는 제외한다.
- 변이(25종)는 선택 대상이 아니다. 해당 계보에 변이 후보가 있는 개체가 Lv.15에서 S1→S2로 진화하는 순간마다 10% 확률로 발동해 수락/거절을 묻는다. 수락하면 변이체(그 자리에서 성장이 끝나는 종착 종)로 진화하고, 거절하면 원래 선택·예약해 둔 대상으로 이어진다. 강제 변이는 없다.
- 변이를 만날 기회를 지나친 개체는 회당 1,000,000토큰·10%, 계보당 30회 실패 시 확정 성공하는 `변이 재도전`으로 그 계보의 변이체를 새 개체로 다시 노릴 수 있다. `계승`(5,000,000토큰)은 종착 종에 도달한 개체를 대상으로 같은 계보의 시작형 신규 개체를 얻어 다른 일반 분기를 다시 육성하는 용도로 쓰인다.
- 새 성장 만렙은 Lv.50이다. 기존 Lv.51~100 저장은 유지하되 추가 레벨 상승은 없다.
- 먹이 한 번으로 여러 진화 기준을 이미 충족한 기존 개체는 가능한 단계를 순서대로 따라잡는다. 다만 그 과정에서 변이 확률이 발동하면 진화를 적용하기 전에 멈추고 수락/거절을 먼저 물은 뒤 나머지 단계를 이어간다 — 이 경우 연쇄 진화가 급여 2회로 나뉠 수 있다.
- 진화는 개체 ID, 레벨, XP 잔여분, 친밀도, 별명, 유니크 컬러, 획득일과 대표 지정을 유지하고 종 ID와 발견 도감만 갱신한다.
- 단일 부모 진화(일반·분기·특수·변이)는 부모와 같은 기본 체형과 최소 두 개의 시각적 상속 특징을 유지한다. 혼합 진화는 두 부모 각각의 특징을 최소 하나씩 보여야 한다. 변이는 같은 종을 유지하면서 실루엣·기관·재질 중 최소 두 항목이 달라져야 한다.
- 진화도감은 현재 카탈로그의 최대 4단계·총 6카드·단계당 3분기까지 372×620 한 화면에 스크롤 없이 표시하고, 이 상한을 넘는 미래 데이터에만 제한적 스크롤을 허용한다.
- 기존 세이브가 이미 `mixed` 종을 보유한 경우 삭제하거나 다른 종으로 바꾸지 않는다. 해당 개체의 진화도감에는 실제 현재 혼합형 카드 하나만 표시하고, 일반 진화 계보 밖의 융합 수집품이라는 안내를 보여 주며 부모 이력을 추정하지 않는다.
- macOS의 기존 활동량 등급 확률과 ORIGIN 천장은 비활성 레거시 규칙이며, 500,000토큰 가격과 유니크 컬러 0.1%는 유지한다.
- 256종 전체를 완주하는 것은 이 진화 경제의 목표가 아니다. 기존 240종 기준 실측은 최소 육성 개체 105마리, 먹이 비용 8,743,500,000토큰(약 87.4억), 주간 5,000,000토큰 적립 기준 약 33.6년이었다. 원초 계보 16종 확장분을 포함한 경제 재실측 전까지 이 수치는 하한선으로만 사용하며 `256종 완성`을 목표로 표현하지 않는다.

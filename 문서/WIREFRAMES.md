# 화면 와이어프레임 맵

저장소 외부에서 전달받은 초기 디자인 핸드오프(`DAEMON.dc.html`)에 20개 시안이 나와 있습니다. 원본 파일은 이 저장소에 포함하지 않습니다. 시안 id(1a, 1b, 2a…)는 그 파일 기준입니다. 아래에서 채택이 필요한 항목은 굵게 표시했습니다.

## macOS 메뉴 막대 앱 핵심 구조 (확정)

### 작은 팝오버 — 기본 화면

1. PunchGrow 로고와 `보유 토큰`
   - 가챠·육성에 쓰는 현재 잔액
   - 시작 보너스가 포함될 수 있어 금주 사용량과 일치하지 않음
2. `금주 사용량` 누적 막대그래프
   - Claude Code와 Codex 비중을 서로 다른 색으로 구분
   - 이번 주에 실제로 수신·적립한 합계만 표시
   - 사용량 0 + 잔액 있음 상태에서 시작 보너스 안내
3. Claude·Codex 통합 배지
   - `중지됨`, `로그 감시 중`, `방금 수신`, `확인 필요`
   - 텍스트, 심볼, 색을 함께 사용해 색만으로 상태를 전달하지 않음
4. `현재 크리처`와 성장 진행도
   - 이미지, `현재 <등급>`, `성장 잠재력 <최종 등급>`, 레벨, XP, 친밀도, 보유 수, 도감 진행도
   - 2마리 이상이면 좌우 순환 버튼과 `현재/전체` 표시; 0·1마리에서는 불필요한 버튼 숨김
   - 좌우 탐색은 현재 대상만 바꾸고 대표는 바꾸지 않음
   - 대표가 아닌 현재 크리처에는 `대표로 지정` 제공
5. 첫 줄 `대형 먹이`, `특대형 먹이`, `가챠`; 둘째 줄 `대형 구매 · 500K`, `특대형 구매 · 250만`과 각 비활성 이유
   - 먹이는 현재 크리처에게 사용
   - 가챠 성공 시 새 크리처가 현재 대상이 되지만 대표는 그대로 유지
6. 하단 고정 도크 `도감 · 등급표 · 진화 · 설정 · 종료`
   - 도감·설정은 큰 창의 해당 영역을 바로 선택해 연다.
   - 등급표는 `직접 가챠 PROCESS 100%`와 최종 등급별 성장 계보 비율을 분리하고, `ORIGIN 계보 3/60 (5%)`와 `보유 수 · 발견 수/전체 수`를 작은 팝업으로 표시한다.
   - 진화도감은 자동 진화 경로와 최종 등급을 연결해 `성장 잠재력`의 근거를 보여준다.
   - 진화는 현재 크리처의 시작형부터 최종형까지 이미지·이름·등급·획득 여부·분기·자동 경로와 Lv.15·25·40 기준을 진화도감 팝업으로 표시한다.
   - 종료는 다른 이동 버튼과 분리된 전원 아이콘·문구로 항상 보이게 한다.
7. 하단 도크는 398×670 작은 화면 안에서 잘리지 않고 스크롤 없이 표시한다.
8. 대형/특대형 먹이 주기·구매는 클릭 1회 실행. 240ms 누르면 80ms 간격으로 반복을 시작하고 실행마다 8ms씩 단축해 최소 35ms까지 가속하며, 떼거나 동작이 막히면 즉시 중지

### 큰 창

`Window(id: "main")`은 최소 900×640의 사이드바 구조로 다음 세 영역만 제공한다. 작은 팝업의 도감·설정 버튼은 공유 선택 상태를 먼저 갱신해 해당 영역을 바로 열며, Connections는 큰 창 사이드바에서 계속 접근한다.

| 영역 | 현재 역할 |
|---|---|
| Collection | 발견·보유·먹이 지표, 이름·ID 검색, 발견한 크리처 카드, 신원을 드러내지 않는 잠긴 미발견 실루엣 |
| Connections | Claude Code·Codex 로컬 로그 자동 발견 상태, 최근 스캔, 개인정보 경계, 진단 정보 |
| Data & Settings | 알림, 사운드, 빛과 움직임 줄이기, `.pgrow` 백업·복원 |

상점과 상세 사용량 통계는 이번 구현에서 제외하고 `COMING LATER`로 안내한다.

### 연결 설정과 사용량 범위

- Connections에서 사용자가 명시적으로 동의한 뒤 Claude `~/.claude/projects`와 Codex `~/.codex/sessions`를 자동 탐색해 10초 간격으로 변경분만 읽는다. 중지는 동의를 철회하며, 연결 해제는 PunchGrow 증분 캐시까지 삭제하되 원본 로그는 건드리지 않는다.
- 최초 발견분은 금주 통계에 표시하되 잔액으로 소급 지급하지 않고, 기준선 이후 새 증가분만 지급한다.
- Claude/Codex 배지는 수집이 활성화되어 해당 디렉터리를 정상 감시하면 `로그 감시 중`으로 표시한다. 로그 파일이 아직 없어도 정상 감시 상태이며, 새 증가분을 적립하면 10초간 `방금 수신` 후 다시 `로그 감시 중`으로 돌아간다.
- 로그 원문·프롬프트·응답·프로젝트명·절대 경로는 저장하거나 외부 전송하지 않는다.

### 가챠 표시 규칙

- 직접 가챠 결과는 60종 PROCESS 시작형 중 하나며 등급 확률은 PROCESS 100%
- 결과 카드는 `현재 PROCESS`와 `성장 잠재력 <최종 등급>`을 동시에 표시하고, 자동 진화 경로를 확인할 수 있는 `진화` 진입점을 제공
- ORIGIN으로 끝나는 시작형은 `ORIGIN 계보` 또는 `성장 잠재력 ORIGIN`으로 표시하고 `ORIGIN 획득`으로 표시하지 않음
- ORIGIN 계보 확률은 현재 3/60=5%로 카탈로그에서 파생한 잠재력 통계이며 직접 ORIGIN 가챠 확률이 아님
- `origin-reveal` 전용 공개는 실제 현재 종이 ORIGIN인 개체를 보유한 상태에만 예약하며, ORIGIN 계보 PROCESS 획득에는 실행하지 않음
- ORIGIN 전용 창은 시스템·앱 동작 줄이기와 `연출 건너뛰기`를 지원하며 모든 경로가 같은 공개 완료 상태로 끝남
- 전용 창을 닫아도 팝업을 자동으로 다시 열지 않음. 실제 ORIGIN인 해당 개체는 세션 현재 크리처로 유지되므로 다음 수동 팝업 열기에서 보임
- 모든 획득 크리처는 도감과 보유 목록에 등록하되 대표 크리처를 자동 변경하지 않음

### 메뉴 막대 상태 표시

- 현재 구현은 메뉴 막대에 고정 `leaf.fill` 아이콘을 사용하고, 수집 상태는 팝업 내부의 Claude·Codex 통합 배지에서 표시한다.
- `중지됨`: 현재 수집하지 않음
- `로그 감시 중`: 로컬 서비스가 실행 중이며 새 사용량을 감시하지만 최근 적립 이벤트가 없음
- `방금 수신`: 검증된 이벤트가 실제로 적립된 뒤 10초 동안
- `확인 필요`: 서비스 오류 메시지가 있음

세부 색상, 크기, 간격, 정확한 애니메이션 값은 네이티브 프로토타입 구현 후 실제 화면을 보며 조정한다.

## 기술 구현 가능성 검증 (2026-07-31 완료)

둥지(홈) 화면을 실제 Expo Router + React Native 코드로 구현해서 1b 디자인이 문제없이 구현되는지 확인했다. 결과: 기술적으로 문제없음.

- `app/(tabs)/_layout.tsx` — 5개 탭 네비게이션(둥지·먹이·아레나·도감·나) 구성, 활성 탭 색상은 `colors.fuel`
- `app/(tabs)/index.tsx` — 1b 스펙(헤더+스트릭배지, 크리처 카드+LV배지+XP바, 스탯 타일 3개, 먹이 대기열 3건) 구현, mock 데이터 사용
- `constants/theme.ts` — 색상 8종, 폰트 토큰. 5개 화면 파일 모두 이 토큰만 사용(하드코딩 색상 없음)
- `hooks/useAppFonts.ts` — Space Grotesk/JetBrains Mono 로딩, 로딩 실패 시에도 렌더링이 멈추지 않도록 에러 처리 포함

- architect 리뷰(조건부 승인) 후 지적된 저비용 항목(탭 활성색, 스탯 첫 항목 강조색, 대기열 카운트 수동 상수화) 반영 완료

## 화면별 핵심 상호작용 (설계 의도, 미구현)
